# SQL Server session manager

The screen reads telemetry through `RuntimeConnection::session_telemetry`, which is implemented by the SQL Server runtime connection backed by `tedious-rs`. PostgreSQL and other providers use the unsupported capability response. The Tauri surface exposes only typed session telemetry and session termination; it does not accept SQL text.

Each refresh sends one read-only batch that joins `sys.dm_exec_sessions`, `sys.dm_exec_requests`, and `sys.dm_exec_connections`, then uses `sys.dm_exec_sql_text` for the active or most recent batch. The response includes request counters, wait and client details, transaction state, statement offsets, and progress values. Statement offsets are UTF-16 byte offsets and are decoded in Rust. Large counters are serialized as decimal strings to preserve their integer values in JavaScript.

The SQL Server runtime supports SQL Server 2005-era DMV columns used by this batch. Duration is computed from day and sub-day differences so it does not depend on `DATEDIFF_BIG`. SQL Server 2019 and earlier require `VIEW SERVER STATE` to see all sessions. SQL Server 2022 and later require `VIEW SERVER PERFORMANCE STATE`. Azure SQL Database has database-scoped DMV behavior and is not claimed as a supported server-wide session view. Permission errors retain SQL Server number, state, class, server, procedure, line, and message.

Session termination is a separate destructive command. The application validates the positive integer and rejects the current monitor SPID. The SQL Server adapter checks `@@SPID` again while holding the same physical connection lock that executes `KILL`, then interpolates only that validated integer. SQL Server requires `ALTER ANY CONNECTION` for `KILL`; Orbit does not grant permissions. A server permission failure remains an error in the confirmation dialog.

SQL text remains in the live IPC response and screen state only. It is not written to connection profiles, application logs, or analytics. Polling starts while the screen is mounted with an active SQL Server connection, uses a per-connection single-flight request, and schedules the next refresh only after the previous one completes.

`tedious-rs/tests/integration/orbitsql_ui_database_adapters.rs` contains an ignored live SQL Server telemetry test using the existing `ORBITSQL_TEST_SQLSERVER_*` integration profile. It is ignored in the normal suite because this repository's Compose test environment provisions PostgreSQL, MySQL, and MariaDB, but no dedicated SQL Server fixture. The test must be run with a dedicated SQL Server profile that permits DMV reads. It performs no writes. A real `KILL` integration test is intentionally not part of the default suite because terminating an unrelated session is destructive; integer validation, monitor-session protection, and the command path are covered without killing a live process.
